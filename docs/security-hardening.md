# Security hardening: local demo vs production, and OWASP API Top 10 mapping

Scope: this repository (a self-built learning project). Statements marked **implemented** point at code that exists and, where noted, at a test that ran
(`docs/core-service-validation.md`: core-service 179 tests, 0 failures, plus a 57-check HTTP smoke test; whole backend 292 tests, 0 failures). **Not executed** means the code exists but needs Docker
(PostgreSQL, Redis, RabbitMQ, MongoDB) and was never run. **Gap** means it is not implemented. No penetration test, dependency audit (`npm audit`,
OWASP Dependency-Check), container scan or threat-modelling workshop was performed.

## 1. Local demo posture vs production posture

The `local` profile is designed to be convenient and is **not** safe to expose. The `docker` profile removes the worst conveniences but is also not a
finished production configuration (never executed).

## 2. Controls that exist, by layer

- **Edge (gateway).** Correlation id validated against `[A-Za-z0-9._-]{1,64}`; HS256 signature and expiry check; token bucket rate limit keyed by JWT subject or socket peer (client `X-Forwarded-For` is replaced, never trusted for limiting); contract-shaped errors; upstream timeouts 2 s connect and 30 s response; actuator on a separate port. **Implemented** (13 tests with stub upstreams; slow-upstream 504 path untested).
- **Core authentication.** `JwtService` (HS256, issuer check, 5 s clock skew, claims validated), `jti` revocation on logout shared across nodes, BCrypt cost 10, dummy-hash verification when tenant or user is unknown, one generic "Invalid credentials" message, login/registration limiter keyed by IP and account with bounded memory, `alg=none`/tampered/expired tokens rejected (tested in `AuthApiTest`).
- **Authorization.** Role hierarchy `ADMIN > MANAGER > AGENT`, `CUSTOMER` outside it; `@PreAuthorize` on privileged endpoints (`RoleMatrixTest` is an endpoint-by-role matrix); object-level checks in services (customers see only their own tickets and PUBLIC comments, may only reopen).
- **Tenant isolation.** Tenant from the verified token only; Hibernate tenant filter on every transaction; explicit tenant predicates; `@PrePersist` guard; composite FKs; tenant-keyed cache; `ArchitectureRulesTest` blocks controllers taking tenant parameters and entities leaving controllers; optional PostgreSQL RLS (not executed).
- **Input handling.** Jakarta Validation on DTOs; whitelisted sort fields; `size` 1..100; `LIKE` wildcard escaping in search; `Idempotency-Key` format regex; workflow definitions validated (no scripts, SpEL/EL markers rejected, size caps); log-injection-safe correlation id; request bodies never logged.
- **Output handling.** DTOs only (never entities); error bodies without stack traces (`include-stacktrace: never`, `include-message: never`); React escapes output and the code base avoids `dangerouslySetInnerHTML` per `frontend/README.md`.
- **Browser.** Token in memory plus `sessionStorage` (not `localStorage`); stateless API, no cookies, so CSRF protection is disabled on purpose; tenant-first query keys and cache clear on logout; 401 clears the session.
- **AI safety.** Mock provider by default; ticket text is treated as data: NFKC normalisation, zero-width and control character removal, HTML stripping, instruction-like sentences dropped, secrets and PII patterns redacted, length bounded; provider output validated against candidate lists and cleaned (URLs removed); suggestions stored as inert `PENDING_REVIEW`; a human approval step is the only way to post a reply; atomic compare-and-set approval; per-tenant rate limit; bounded worker pool; circuit breaker; the optional HTTP provider is https-only, no redirects, and fails closed when unconfigured. The application refuses to start with AI fault injection on under the docker profile. **Best effort, not a guarantee**: pattern-based sanitising cannot catch every paraphrased injection; the architectural guarantee is "nothing is applied without approval".

## 4. Authentication, tenant resolution, authorization and data isolation: hardening checklist by concern

1. **Authentication**: move to an IdP (OIDC) or at least RS256 with `kid` rotation; add refresh tokens and a per-user token version to make deactivation immediate; the short "not revoked" cache (3 s) now protects the DB, at the price of a revocation delay of at most that TTL on nodes other than the one that handled the logout (`cx.security.revocation-negative-cache-seconds=0` removes it).
2. **Tenant resolution**: keep tenant only in the signed token; add a tenant status check (suspended tenants) at token verification; never accept tenant ids in controllers (enforced by `ArchitectureRulesTest`).
3. **Authorization**: keep `@PreAuthorize` plus object-level checks; add a test per new endpoint to the role matrix; document customer-visible vs staff-visible fields.
4. **Data isolation**: run RLS in production with a non-owner role; forbid `JdbcTemplate` and native queries outside reviewed repositories; add an automated cross-tenant test per new entity; give the document store the same guarantee (Mongo isolation is application-enforced only).

## 5. Secure-by-default decisions already taken

Fail closed on missing secrets in the docker profile; no default Spring user; 404 over 403 for foreign objects; PUBLIC-only AI replies; append-only audit; per-transaction (`SET LOCAL`) tenant binding for RLS so pooled connections cannot leak a tenant; redaction of credential-like values before audit storage and of PII-like values before AI calls; bounded memory in limiters and caches.

## 6. Priority list if this were taken toward production

1. Set `CX_SEED_ENABLED=false`, (notification-service dummy fallback credentials: removed), protect or disable Swagger and Prometheus on public ports.
2. Execute the docker profile end to end on a Docker host (migrations, RLS tests, Redis and RabbitMQ ITs, Mongo IT) and fix whatever breaks.
3. Replace shared-secret HS256 with an IdP or RS256; add refresh tokens, MFA/SSO, tenant suspension.
4. Broker trust: per-service users, least-privilege vhost permissions, recipient/tenant validation in consumers.
5. Add retention jobs (outbox, processed events, audit archival), request-size limits, per-tenant quotas, CAPTCHA/approval on registration.
6. CI: dependency and container scanning, SAST, secret scanning, ZAP/API fuzzing against a seeded throwaway environment.
